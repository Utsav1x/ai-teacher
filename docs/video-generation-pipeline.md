# AI Teaching Video Generation Pipeline

## Overview

This document describes the complete architecture for generating photorealistic AI teaching videos from lessons generated by the Teacher Agent.

**Goal**: Replace the simple animated Maya avatar with a multi-scene, photorealistic AI teacher video featuring:
- Professional human AI avatar (not cartoon/robot)
- Natural speech with lip synchronization
- Dynamic educational visuals (diagrams, code, formulas)
- Scene transitions that match the teaching flow
- Pause points for interactive questions

## Architecture

```
Teacher Agent → AILesson → Scene Planner → D-ID Video Generation → Video Player → AI Classroom
```

### Components

1. **Scene Planner** (`lib/video/scene-planner.ts`)
   - Converts `AILesson` into structured `ScenePlan`
   - Decides WHAT to teach and in what order
   - Marks pause points for student interaction
   - Output: Array of `Scene` objects with narration, layout, visuals

2. **D-ID Provider** (`lib/video/did-provider.ts`)
   - Thin wrapper over D-ID REST API
   - Uses `/clips` endpoint (V3 Pro Avatar presenters)
   - Server-side only; API key never exposed to browser
   - Supports both pre-built presenters and custom photo avatars

3. **Generation API** (`app/api/teacher/generate-video/route.ts`)
   - POST endpoint: receives lesson → builds scene plan → submits to D-ID
   - Returns initial `VideoJob` with clip IDs in `'polling'` state
   - Limits scenes per job to avoid credit burn

4. **Status API** (`app/api/teacher/video-status/route.ts`)
   - POST endpoint: receives current job → polls D-ID for each pending clip
   - Returns updated job with `'done'` clips and video URLs
   - Client polls this endpoint every 4 seconds

5. **Video Player** (`components/app/lesson-video-player.tsx`)
   - Self-contained React component
   - States: idle → preparing → polling → ready → playing → question → end
   - Plays clips sequentially with `<video>` element
   - Pauses at question scenes; calls `onQuestionReached(questionIndex)`
   - Transport controls: play, pause, resume, replay, stop

6. **Classroom Integration** (`app/(app)/classroom/page.tsx`)
   - Replaces `LessonVideoButton` with `LessonVideoPlayer` in right sidebar
   - Wires `onQuestionReached` to trigger interactive question phase
   - Preserves existing avatar, lesson flow, AI state machine unchanged

## Scene Plan Structure

A `ScenePlan` contains:
- `lessonId`, `lessonTitle`, `language`
- Array of `Scene` objects
- `totalDurationSeconds` (estimated)

Each `Scene`:
```typescript
{
  index: number
  type: 'intro' | 'concept' | 'visual' | 'example' | 'summary' | 'question' | 'completion'
  narration: string                 // TTS script
  layout: 'full' | 'left-panel' | 'pip' | 'hidden'
  visual?: string                   // Fence-stripped code/diagram/formula
  visualType?: VisualType           // code | formula | diagram | timeline | table | graph
  visualLabel?: string              // "Equation" | "Diagram" etc
  onScreenText?: string             // Title overlay
  durationSeconds: number           // Estimated
  transition: 'cut' | 'fade'
  pauseForInteraction: boolean      // True for question scenes
  questionIndex?: number            // Which question this scene represents
}
```

### Scene Flow Example

For a typical lesson:
1. **intro** — Teacher introduces topic (full-screen avatar)
2. **concept** — Core teaching with visual (avatar left, visual right)
3. **visual** — Visual fills screen, avatar PiP, teacher continues
4. **summary** — Key points recap (full-screen avatar)
5. **question** — Checkpoint question (PAUSES HERE for student)
6. **completion** — Wrap-up and next topic (full-screen avatar)

## Classroom Flow

1. **User enters classroom** → lesson loads (from cache or generates fresh)
2. **Right sidebar** → "Generate AI Teaching Video" button appears
3. **User clicks** → `startGeneration()` fires
   - Calls `/api/teacher/generate-video`
   - Receives initial job with clip IDs
4. **Polling begins** → every 4s, calls `/api/teacher/video-status`
   - Updates progress bar
   - Shows "Processing X/Y scenes…"
5. **All clips ready** → autoplay begins
   - First scene plays in `<video>` element
   - Scene type badge shows in corner
   - Progress dots at bottom
6. **Clip ends**:
   - If scene is question → pause, set `playerState = 'question'`, fire `onQuestionReached(index)`
   - Classroom shows interactive question UI below video
   - Student answers
   - Student clicks "Continue video" → next clip plays
   - Else → automatically advance to next clip
7. **Last clip ends** → fires `onVideoEnd()`
   - Classroom advances to lesson completion phase

## Key Design Decisions

### Why D-ID over HeyGen?

- **Simpler API**: D-ID `/clips` endpoint is REST-based, takes `presenter_id` + `script.input`, returns clip ID. No need to list avatars first or manage complex template structures.
- **Pre-built presenters**: Professional human avatars out-of-the-box (Amber, Adam). No need to host avatar images.
- **Free trial**: Includes credits for hackathon testing without card.
- **Documentation**: Clear REST API docs vs HeyGen's v2→v3 transition confusion.

### Why Scene-Based Generation?

- **Subject-aware**: Different scenes for intro, concept, visual deep-dive, question, completion.
- **Pause control**: Question scenes pause for interaction; others flow automatically.
- **Visual integration**: Visual scenes can go PiP or full-screen; concept scenes split avatar/visual.
- **Replayable**: Each scene is a separate clip; failed scenes don't kill entire video.

### Why Client-Side Polling vs Webhooks?

- **Simplicity**: No webhook endpoint to secure/deploy.
- **Real-time feedback**: Progress bar updates live; user sees "3/6 scenes ready…"
- **Vercel compatibility**: Webhooks require public endpoint; polling works on any Next.js deployment.

### Why Separate from MockTeacherEngine?

- **Orthogonal concerns**: Video generation is a presentation layer; `TeacherEngine` is teaching logic.
- **No backend changes**: Existing lesson flow, RAG pipeline, database unchanged.
- **Fallback intact**: `LessonVideoButton` (canvas recorder) remains available for users without D-ID key.

## Limitations & Future Work

### Current Limitations

1. **Max 6 scenes per job** — to avoid burning credits during dev. Configurable via `MAX_SCENES_PER_JOB`.
2. **No scene composition** — each D-ID clip is standalone. Visuals are not composited into the frame; they're mentioned in narration.
3. **Single presenter** — uses default Amber avatar. Custom avatars require uploading consent video (V3 Instant Avatar).
4. **No multi-language voice switching** — D-ID uses default voice per presenter. Would need `voice_id` mapping per language.
5. **D-ID credit cost** — ~1 credit per 30s. A 6-scene lesson ≈ 6 credits. Free trial ≈ 20-30 clips.

### Future Enhancements

1. **Full scene composition** — use a video composition API (Remotion, Hyperframes) to overlay visuals, diagrams, code onto D-ID avatar clips.
2. **Custom avatars** — let teachers upload photo + consent video → generate personalized teaching videos.
3. **Voice customization** — map lesson language → D-ID voice ID for natural multilingual support.
4. **Background scenes** — change background per scene type (classroom for intro, blackboard for concept, lab for example).
5. **Adaptive difficulty in video** — generate multiple question scenes at different difficulties; select which to show based on student's running performance.
6. **Downloadable video** — stitch all clips into single MP4 for offline viewing (similar to existing `LessonVideoButton` recorder).

## Testing

### Manual Test Flow

1. Set `DID_API_KEY` in `.env.local`
2. Start dev server: `pnpm dev`
3. Navigate to `/classroom`
4. Load a lesson (generates or uses cache)
5. Click "Generate AI Teaching Video" in right sidebar
6. Watch progress: "Preparing → Generating → 3/6 scenes ready → Ready"
7. Video autoplays
8. First few clips play → reaches question scene → pauses
9. Answer question below video
10. Click "Continue video" → remaining clips play
11. Last clip ends → classroom advances to completion
