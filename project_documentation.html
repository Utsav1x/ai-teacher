Project Documentation

Lumina — an AI teacher that adapts

A web application that turns an uploaded document or a bare topic into a personalised, spoken, adaptive teaching session — grounded in the learner's own material and delivered by an animated AI teacher.

1 · Problem statement

Digital learning platforms offer pre-recorded lectures or text chatbots. Neither teaches. A recorded lecture cannot notice that you did not follow the third paragraph; a chatbot answers the question you asked rather than the one you should have asked.

A human teacher does something different: they plan, explain, demonstrate, ask, listen to the answer, work out which misunderstanding produced it, and explain again from a different angle. Lumina implements that loop.

2 · Solution overview

The learner uploads material — PDF, DOCX, PPTX, TXT, MD — or names a topic, and states their level, language, available time and goal. Lumina then:

  1. Parses, chunks and embeds the document into a vector store
  2. Retrieves the passages relevant to the topic
  3. Generates a structured lesson plan sized to the stated time
  4. Teaches it aloud through an animated avatar in the chosen language
  5. Asks graded checkpoint questions
  6. Diagnoses the specific misconception behind a wrong answer
  7. Re-explains using a deliberately different analogy, then re-tests
  8. Adjusts difficulty from performance and carries weak concepts into the next lesson
  9. Produces a report and an exportable teaching video

5 · AI/ML models used

PurposeModelNotes

Embeddingsgemini-embedding-001Requested at 768 dimensions to match the schema
NarrationMicrosoft Edge neural voicesPrimary — no key, no quota, 322 voices
Narration fallbackgemini-3.1-flash-tts-previewUsed only if Edge is unreachable
Live in-page speechWeb Speech APIBrowser-native, zero latency
Design decision

Free-tier Gemini quota is granted per model per day and is small — 20 requests/day on some models. Generation therefore walks a chain of five models, each with an independent quota, and only quota or access errors advance it. A genuine failure still fails fast rather than being retried five times.

6 · RAG implementation

  1. Upload — the file goes to Supabase Storage; a materials row records it.
  2. Parse — a per-format parser extracts structured sections. PDFs are read page by page via pdf-parse v2, preserving page numbers; DOCX via mammoth; PPTX slide by slide.
  3. Chunk — sections are split into overlapping chunks carrying section title, page number and token count.
  4. Embed — chunks are embedded in batches of 100 via batchEmbedContents at 768 dimensions.
  5. Store — vectors go into material_chunks.embedding, indexed with ivfflat under cosine distance.
  6. Retrieve — the topic is embedded and matched by match_material_chunks, returning the top 8 above a 0.45 similarity floor, scoped to the learner.
  7. Inject — retrieved passages are formatted with relevance scores and placed in the generation prompt.

Grounding is verifiable in the server log: Injecting N chunks as context appears before generation, and lessons contain specifics that could not be inferred from a filename.

Dimension constraint

gemini-embedding-001 returns 3072 dimensions by default, which the vector(768) column rejects. The pinned SDK exposes no dimension parameter, so embedding calls go over REST with outputDimensionality: 768, and the provider throws if a returned vector is ever the wrong length rather than letting a mismatch reach the database.

7 · Prompt and agent architecture

Rather than one long conversational prompt, teaching is split into three contracts, each returning strict JSON. Every prompt lives in lib/ai/teacher/prompts.ts, so teaching behaviour is changed by editing prompts, never the provider.

ContractReturnsNotable instruction
LESSON_GENERATION Title, objective, narrative, key points, visual payload, sections, three graded questions, re-explanation, next topic Re-explanation must use a different analogy from the teaching narrative
ANSWER_EVALUATION Correctness, feedback, correct answer, re-explanation, misunderstandingDetected Detect the specific misconception, not just right or wrong
ASK_TEACHER Answer plus follow-up suggestions Stay within the current lesson's scope

Responses are validated and normalised before reaching the UI: missing fields throw with a named field, question shapes are coerced, and the older single-question format is still accepted so cached lessons keep working.

8 · Personalisation approach

Four inputs shape every lesson — level, language, goal and available time — and three signals accumulate as the learner works:

  • Covered topics. Previous lesson titles are passed forward, with an instruction not to repeat what the learner already knows.
  • Weak concepts. Every missed checkpoint records the concept it tested. Those are injected into the next lesson's prompt, which is told to reconnect to them, explain from a different angle, and test them directly in the easy checkpoint.
  • Difficulty state. The running answer history moves the target difficulty up or down.

Time drives structure directly: a 20-minute request yields four five-minute sections whose minutes sum to the request.

9 · Assessment methodology

Each lesson carries three checkpoints, tagged with difficulty and with the concept under test:

TierTests
easyRecall — a learner who followed the explanation should pass
coreGenuine understanding of the central idea
stretchApplication to a situation the explanation never covered

A correct answer steps difficulty up; a wrong one steps it down, and the interface says which is happening. Wrong answers trigger diagnosis: the misconception is named, re-explained with a different analogy, and the learner can retry the same question or drop to an easier one.

The final report is computed from what was actually answered — strong and weak areas are the real concept names from the generated lesson, and mastery derives from the achieved score.

10 · Multilingual implementation

  • Generation. The requested language is stated in the learner profile and reinforced by an explicit rule covering every learner-facing string. Technical terms may retain their English form in parentheses, which is how these subjects are normally taught in Indian classrooms.
  • Cross-language grounding. Retrieved passages and output language are independent, so an English document can be taught in Hindi and vice versa.
  • Narration. The language maps to a BCP-47 tag and then to a matching neural voice; 21 Indian voices are available.
  • Lip-sync. Visemes are mapped from both Latin and Devanagari characters, so Hindi and Hinglish animate rather than sitting still.
  • Cache correctness. The lesson cache key includes language, so changing language regenerates rather than reusing.

11 · Voice implementation

Two paths, chosen by context:

ContextEngineWhy
Live classroomWeb Speech APIZero latency, no network, no quota
Video exportEdge neural TTS via /api/teacher/speakReturns audio bytes, which can be mixed into the recording
Why two engines

speechSynthesis writes directly to the output device and cannot be routed into a MediaStream. It is ideal live and useless for recording. Edge TTS returns an MP3, which is decoded through Web Audio and mixed into the video — so the exported file has narration without asking the viewer to share their screen.

Lip-sync uses six visemes (the Preston Blair set reduced for real time). Live, it is driven by boundary events with an estimated fallback, because those events are optional in the spec and most non-English voices never emit them. During export, clip duration is known from decodeAudioData, so timing is exact.

12 · Avatar and video generation

The avatar is drawn as SVG in the live classroom and re-drawn on a canvas for export. It is not a pre-rendered clip, and that is the point: pre-rendered avatar video cannot say something different when a learner is confused, which is precisely what the adaptive loop requires.

Export composes a 1280×720 video at 30 fps containing the avatar with live lip-sync, the current slide, burned-in captions and a progress bar. The recorder drives its own narration and waits for each clip to finish, so captions, mouth and slides cannot drift apart.

Encoder constraints

Chrome reports mp4a.40.2 (AAC) as supported and then throws EncodingError at record time whenever an audio track is attached, producing a zero-byte file. The audio codec is therefore left unspecified so Chrome negotiates one it can encode. Audio is also proven — first clip fetched and decoded — before a track is attached, because a track carrying no samples stalls the muxer and truncates the video to under a second.

Painting runs on setInterval, not requestAnimationFrame, which browsers suspend entirely in hidden tabs.

14 · Setup instructions

Full detail in docs/setup.md. In brief:

pnpm install
cp .env.example .env.local     # add Supabase keys + GOOGLE_AI_API_KEY
                               # set NEXT_PUBLIC_USE_REAL_AI_TEACHER=true
# run all 7 files in supabase/migrations/ in filename order
pnpm dev                       # http://localhost:3000
Two traps

Without NEXT_PUBLIC_USE_REAL_AI_TEACHER=true the app silently serves mock lessons. Skipping migrations 5 and 6 leaves retrieval returning zero chunks while lessons still generate — grounding fails without an error.

Do not develop inside a cloud-synced folder; sync clients break Turbopack's .next writes.

15 · Deployment instructions

  1. Push to GitHub and import the repository into Vercel.
  2. Set NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, GOOGLE_AI_API_KEY, NEXT_PUBLIC_USE_REAL_AI_TEACHER=true and optionally GEMINI_MODEL.
  3. Run all migrations against the production Supabase project.
  4. Add the deployment origin to Supabase → Authentication → URL configuration, and to each OAuth provider's callback list.
  5. Deploy. pnpm build then pnpm start works for any Node host.

/api/teacher/speak opens a WebSocket and is pinned to the Node runtime; it will not work on an edge runtime.

16 · Known limitations

  • Free-tier quota. Gemini limits are per model per day and small. The model chain mitigates this but does not remove it.
  • Generation latency. A lesson takes roughly 30 seconds. It is generated once and cached for the classroom, but the first wait is unavoidable.
  • Lip-sync is approximate live. The Web Speech API exposes word boundaries at best, so live sync is word-level. Export sync is exact.
  • Exported audio is Opus in MP4. Chrome cannot encode AAC here. Modern players handle it; QuickTime and PowerPoint may play the video silently.
  • Edge TTS is unofficial. It uses the endpoint behind Edge's Read Aloud. Stable in practice, but not a published API — hence the Gemini fallback.
  • Coarse DOCX chunking. The DOCX parser emits a single section per document, so retrieval is less precise than for PDFs.
  • Language switching is per-lesson. Changing language regenerates the lesson rather than translating in place mid-session.
  • Progress is per-lesson, not per-section. Resuming returns to the lesson, not the exact sentence.
  • No offline mode. Generation, embedding and export narration all require network access.
